# Dataset Details

**Project:** KGCR — Knowledge Graph-Based Cloud Configuration Recommendation
**Course:** BCSE355L Cloud Architecture Design Project, Phase-I

The dataset is **generated, not downloaded**. No external dataset is used and no real
financial-sector data is involved. This is stated openly here and in FD-05 rather than dressed up
with an external source the project does not have.

---

## Corpus A — synthetic intent-first estates (primary dataset, present)

| Field | Value |
|---|---|
| **Dataset name** | KGCR Corpus A — intent-first synthetic AWS estates |
| **Source** | Generated by `src/backend/kgcr/corpus/` (this repository). Not collected, not downloaded |
| **URL** | https://github.com/uditdaftary/KGCR_Cloud_Project_2026 — generator source and manifest. The estates themselves are not committed; they re-derive byte-for-byte from `(count, seed)` |
| **Size** | 29 KB manifest committed; the generated estate set is approximately 8 MB of JSON for the 180-estate configuration used in the reported experiment |
| **Number of records** | **180 estates**, one seed family each — 64 payments API, 60 internal reporting, 56 customer data platform. **2,331 AWS resources** in total, forming graphs of 2,331 nodes and 1,615 `DEPENDS_ON` edges |
| **Number of features** | **17 structural features** per estate for the reconstruction model: `n_resources`, `n_subnets`, `n_public_subnets`, `n_private_subnets`, `az_count_estimate`, `has_igw`, `has_nat`, `has_cloudtrail`, `has_cardholder_db`, `has_glue_pii`, `has_lake`, `has_reporting_instance`, `has_lb`, `n_iam_roles`, `n_iam_policies`, `max_tag_keys`, `instance_size_rank`. The prediction targets are **7 intent axes**: archetype, AZ spread, network layout, logging posture, IAM shape, tagging discipline, scale |
| **Data type** | Structured JSON. Per estate: Terraform JSON (`.tf.json`) of real `aws_*` resource types, the ground-truth intent (`.intent.json`), and the dependency graph (`.graph.json`) |
| **Licence** | None required — self-generated by this project, covered by the repository's MIT licence |
| **Purpose** | Two uses. (1) Training and evaluating intent reconstruction: because the intent is sampled *first* and the estate rendered from it, every estate carries its originating intent as free ground truth. (2) Serving as the clean parent corpus into which defects are injected with known ground truth |
| **Preprocessing required** | Generation is the preprocessing: sample intent → render estate → build dependency graph → write manifest, all deterministic in `(count, seed)`. For the model, structural feature extraction reads resources and topology only and never touches the intent. Splitting is at estate level by seed family, with a leakage guard, so no estate's structure informs its own evaluation |

**Regeneration** (deterministic, no AWS account or Terraform binary needed):

```bash
python src/ml_model/preprocessing.py --count 180
```

**Split used in the reported experiment:** 126 train / 30 validation / 24 test estates. The model
fits on train + validation (156 estates) and is evaluated on the 24 held-out test estates.

## Defect corpus — injected defects with ground truth (present)

| Field | Value |
|---|---|
| **Dataset name** | KGCR defect corpus, classes DF-1 to DF-7 |
| **Source** | Generated by `src/backend/kgcr/defects/` from Corpus A parents |
| **Number of records** | **12 relational (DF-7) estates** — 4 parent estates × 3 injection variants: indirect internet reachability, transitive trust chain, and `iam:PassRole` privilege escalation. Single-resource classes DF-1 to DF-6 are injected on demand from the same parents |
| **Number of features** | Ground truth per defect instance: defect class, injection site, control URI, expected finding, and the evidence path through the graph |
| **Data type** | Structured JSON, same estate format as Corpus A plus a defect manifest |
| **Licence** | None required — self-generated |
| **Purpose** | Measure the central claim: whether a graph representation detects defects that single-resource policy engines cannot reach. DF-7 defects are wired so that every individual resource in the chain remains compliant and the chain terminates at a genuinely sensitive sink (cardholder data or PII) |
| **Preprocessing required** | Injection is deterministic from the parent estate and seed. Evaluation feeds resource-only Terraform JSON to Checkov as a subprocess, because its `terraform_json` parser rejects a `provider` block |

**Result on this corpus:** the graph recovers all 12 relational paths, while Checkov — including its
CKV2 graph checks — returns a verdict on the sensitive sink that is byte-identical to the clean
parent estate in all 12 cases. Evidence: `results/p4_df7_checkov_evidence.json`.

## Why synthetic

Real regulated cloud estates are not publishable, and a corpus mined from public repositories
carries no ground truth about what the configuration was *intended* to achieve. Intent-first
generation solves both: the intent is known exactly because it was sampled before the estate
existed, and no confidential data is involved. The cost is realism, and Corpus D exists in the plan
specifically to test results against configurations this project did not write.
